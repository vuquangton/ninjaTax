# DISCOVERY: Multi-Database Architecture for ninjaTax

## 1. Research on EF Core Multi-DB Limitations (D1)

### 1.1 SQLite Decimal Handling & Precision Drift
- **Issue**: SQLite has no native `DECIMAL` or `NUMERIC(p, s)` storage class; it stores values in 5 basic classes (`NULL`, `INTEGER`, `REAL`, `TEXT`, `BLOB`). If EF Core maps a `decimal` to SQLite default without explicit type guidance, SQLite may treat it as `REAL` (8-byte IEEE floating-point), causing rounding errors fatal to financial ledger applications (e.g. `1000000.005` becoming `1000000.0049999999`).
- **Solution**: Explicitly configure column type as `TEXT` in SQLite for all monetary `decimal` fields, or rely on EF Core's built-in string conversion for decimals. In EF Core, string-based storage preserves arbitrary precision and exact digit representation upon read/write without precision drift.

### 1.2 PostgreSQL (Npgsql) Specifics
- **Case Sensitivity & Identifiers**: PostgreSQL folds unquoted identifiers to lower-case. Using PascalCase table names like `TaiKhoan` creates quoted identifiers `"TaiKhoan"`.
- **Data Types**: `decimal` maps to `numeric(19, 4)` seamlessly. `long` maps to `bigint` with `bigserial` / identity columns (`GENERATED BY DEFAULT AS IDENTITY`).

### 1.3 MariaDB / MySQL (Pomelo) Specifics
- **Server Version**: Pomelo requires specifying a `ServerVersion` (e.g., `MariaDbServerVersion` or `MySqlServerVersion`). Using static fallback prevents connection failure during offline startup or tool execution.
- **Data Types**: `decimal` maps to `decimal(19, 4)`. `long` maps to `bigint AUTO_INCREMENT`. `bool` maps to `TINYINT(1)` (ensure `TreatTinyAsBoolean=true` in connection string).

### 1.4 SQL Server 2012+ Specifics
- **Data Types**: `decimal` maps to `decimal(19, 4)`. `long` maps to `bigint IDENTITY(1,1)`.
- **Connection Flags**: `TrustServerCertificate=True` and `MultipleActiveResultSets=True` are required for modern local and dev environments.

## 2. Data Type Mapping Strategy (D2)

| C# Domain Type | SQLite | SQL Server (2012+) | PostgreSQL (Npgsql) | MariaDB (Pomelo) |
|---|---|---|---|---|
| `long` (Primary Key) | `INTEGER PRIMARY KEY AUTOINCREMENT` | `bigint IDENTITY(1,1)` | `bigint GENERATED BY DEFAULT AS IDENTITY` | `bigint AUTO_INCREMENT` |
| `long` (Foreign Key) | `INTEGER` | `bigint` | `bigint` | `bigint` |
| `decimal` (Monetary) | `TEXT` (exact decimal string) | `decimal(19, 4)` | `numeric(19, 4)` | `decimal(19, 4)` |
| `bool` | `INTEGER` (0 / 1) | `bit` | `boolean` | `tinyint(1)` |
| `DateTime` | `TEXT` (ISO-8601) | `datetime2` | `timestamp with time zone` / `timestamp` | `datetime(6)` |
| `DateOnly` | `TEXT` (YYYY-MM-DD) | `date` | `date` | `date` |
| `string` | `TEXT` | `nvarchar(n)` / `nvarchar(max)` | `varchar(n)` / `text` | `varchar(n)` / `longtext` |

## 3. DbContext Configuration & Provider Registration Pattern (D3)

### 3.1 Architecture Seam
Isolate provider registration into a dedicated service collection extension:
`DatabaseServiceExtensions.AddMultiDatabaseContext(this IServiceCollection services, IConfiguration configuration, ILogger logger)`

### 3.2 Dynamic Selection & Fallback Rules
1. Read configuration `DatabaseProvider`.
2. Normalize key (`sqlite`, `sqlserver`, `postgresql`, `mariadb`).
3. If null, empty, or unrecognized: log warning, fallback gracefully to `Sqlite`.
4. Validate that connection string exists for chosen provider; throw descriptive `InvalidOperationException` if missing.
5. In `AppDbContext.OnModelCreating`, inspect `Database.IsSqlite()`:
   - If SQLite, bind monetary properties to `TEXT` column type.
   - For all relational providers, apply `.HasPrecision(19, 4)`.

## 4. Migration Strategy (D4)

### 4.1 Provider-Specific Migration Assemblies vs Single Schema
Because SQL Server, PostgreSQL, MariaDB, and SQLite generate different DDL dialects (e.g. `TEXT` vs `nvarchar(50)`, `bigserial` vs `IDENTITY(1,1)`), the enterprise pattern for multi-DB is:
- Default SQLite migrations in the main assembly or `Migrations/Sqlite/`.
- Provider-specific migrations via the `--output-dir` parameter:
  - SQLite: `dotnet ef migrations add <Name> --output-dir Migrations/Sqlite`
  - SQL Server: `dotnet ef migrations add <Name> --output-dir Migrations/SqlServer`
  - PostgreSQL: `dotnet ef migrations add <Name> --output-dir Migrations/PostgreSql`
  - MariaDB: `dotnet ef migrations add <Name> --output-dir Migrations/MariaDb`

### 4.2 Runtime Database Setup
For development and lightweight scenarios:
`await context.Database.EnsureCreatedAsync()` creates schema dynamically matching the active provider without requiring external migration files.
